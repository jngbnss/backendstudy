# 램그스타인 요구사항 명세서

## 1. 서비스 개요

램그스타인은 사용자가 자신의 실패 경험을 공유하는 커뮤니티 게시판이다. 사용자는 실패담을 작성하고, 다른 사용자는 좋아요와 댓글로 반응할 수 있다. 게시글이 실제 실패담이 아니거나 조롱/기만 목적이라고 판단되면 신고할 수 있다.

초기 버전은 게시판형 서비스로 만든다. 이후 인스타그램처럼 팔로우, 피드, 이미지 중심 업로드, 프로필 중심 SNS로 확장할 수 있게 설계한다.

## 2. 목표

- 실패 경험 공유 게시판 제공
- 전체 게시판, 카테고리별 게시판, 인기 게시판 구조 제공
- 좋아요, 댓글, 신고 기능 제공
- 사용자 카테고리 추가 신청 및 관리자 승인 기능 제공
- 관리자 신고 검토 및 게시글/회원 제재 기능 제공
- S3 기반 이미지 업로드 경험 확보
- 향후 SNS 피드/팔로우 구조로 확장 가능한 데이터 모델 확보

## 3. 사용자 유형

| 사용자 | 설명 |
| --- | --- |
| 비회원 | 공개 게시글 목록/상세 조회 가능 |
| 회원 | 글 작성, 수정, 삭제, 좋아요, 댓글, 신고, 카테고리 신청 가능 |
| 관리자 | 카테고리 승인, 신고 검토, 게시글 숨김/삭제, 회원 제재 가능 |

## 4. 핵심 기능

### 4.1 회원

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| USER-001 | 사용자는 이메일과 비밀번호로 회원가입할 수 있다 | Must |
| USER-002 | 사용자는 JWT + Refresh Token 방식으로 로그인할 수 있다 | Must |
| USER-003 | 사용자는 로그아웃할 수 있다 | Must |
| USER-004 | 사용자는 Access Token을 재발급받을 수 있다 | Must |
| USER-005 | 사용자는 닉네임, 프로필 이미지, 자기소개를 수정할 수 있다 | Should |
| USER-006 | 사용자는 탈퇴할 수 있다 | Must |
| USER-007 | 관리자는 회원 상태를 정상/일시정지/영구정지/탈퇴로 관리할 수 있다 | Must |

### 4.2 게시판/카테고리

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| BOARD-001 | 사용자는 전체 게시판에서 모든 공개 게시글을 조회할 수 있다 | Must |
| BOARD-002 | 사용자는 카테고리별 게시판에서 특정 카테고리 게시글을 조회할 수 있다 | Must |
| BOARD-003 | 사용자는 인기 게시판에서 좋아요/댓글 등 기준으로 정렬된 게시글을 조회할 수 있다 | Should |
| BOARD-004 | 회원은 새로운 카테고리를 신청할 수 있다 | Should |
| BOARD-005 | 관리자는 카테고리 신청을 승인/반려할 수 있다 | Should |
| BOARD-006 | 관리자는 카테고리를 활성/비활성 처리할 수 있다 | Should |

### 4.6 댓글

| REPORT-002 | 신고 사유는 허위 실패담, 조롱/기만, 혐오/괴롭힘, 스팸, 기타로 구분한다 | Must |

| REPORT-007 | 관리자 조치는 NONE, HIDE_POST, DELETE_POST, TEMP_SUSPEND_USER, PERMANENT_SUSPEND_USER로 관리한다 | Must |

## 5. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 인증 | JWT + Refresh Token 기반 인증 사용 |
| 토큰 | Refresh Token은 서버 DB에 저장하고 로그아웃 시 폐기 |
| 권한 | 회원/관리자 권한 분리 |
| 보안 | 비밀번호 해시 저장, 입력값 검증, XSS 방지 |
| 업로드 | 이미지 업로드는 S3 Presigned URL 방식 사용 |
| 성능 | 게시글 목록은 페이지네이션 적용 |
| 페이지 | API 페이지 번호는 1-based로 통일 |
| 감사 | 신고 처리 이력과 회원 제재 이력은 삭제하지 않고 보존 |
| 확장성 | 팔로우, 피드, 이미지 다중 첨부로 확장 가능하게 설계 |
